# 칭찬 스탬프 모으기 — 행동 중재 보상 웹앱 기획서

## 1. 프로젝트 개요

### 1.1 프로젝트명
**칭찬 스탬프 모으기**

### 1.2 목적
특수교육대상 학생이 학교생활의 구체적인 행동 목표를 이해하고 실천할 수 있도록 하고, 여러 교사가 동일한 기준으로 즉각적인 긍정적 피드백을 제공하며, 학생이 누적된 성취를 시각적으로 확인할 수 있도록 하는 행동 중재·강화 웹앱이다.

핵심 흐름:

> **행동 단계 실천 → 칭찬 스탬프 획득 → 한 차시 완료 → ⭐ 스타 획득 → 스타 누적 → 30개 달성 → 게임 쿠폰 획득**

### 1.3 주요 사용자
- 학생
- 특수교사
- 통합학급 담임교사
- 전담교사
- 학부모

### 1.4 핵심 설계 원칙
1. **학생에게는 최대한 단순하게**
   - 글보다 그림과 애니메이션 중심
   - 한 화면에서 현재 목표와 보상을 직관적으로 확인
2. **교사에게는 빠르게**
   - 차시 시작 → 행동 항목 확인 → 스탬프 클릭만으로 기록
   - 날짜·교시·교사명은 최소 입력
3. **행동중재 원칙에 맞게**
   - 관찰 가능한 행동으로 목표를 작성
   - 즉각적 강화
   - 일관된 기준으로 여러 환경에서 기록
4. **가정-학교 연계**
   - 학교에서 누적된 스타를 학생과 학부모가 확인
   - 학부모도 필요하면 가정 행동을 별도로 기록할 수 있도록 확장 가능
5. **게임적 요소는 강하게, 기록은 명확하게**
   - 스타 획득 순간의 시각·청각적 보상
   - 누적 스타 수와 다음 보상까지의 진행률을 항상 표시

# 3. 핵심 사용자 흐름

## 3.1 교사

### 차시 시작
1. 학생 선택
2. 차시 유형 선택
   - 강당 단체 활동
   - 국어·수학 특수학급
   - 통합학급
3. 날짜 자동 입력
4. 교시 선택
5. 교사 이름 자동 입력 또는 선택
6. 행동 체크 화면 표시

### 수업 중
각 행동을 성공했을 때 해당 행동의 **「좋아요 👍」 스탬프 버튼**을 누른다.

예:

```text
┌─────────────────────────────┐
│ 오늘의 칭찬 스탬프            │
│ 2026.10.31  2교시            │
│ 선생님: 김○○                │
├─────────────────────────────┤
│ 👍 선생님께 인사하기     [✓] │
│ 👍 자리에 앉기           [✓] │
│ 👍 활동에 집중하기       [ ] │
│ 👍 친구들과 함께 행동하기 [ ]│
│ 👍 끝나고 인사하기       [ ] │
├─────────────────────────────┤
│        ⭐ 0 / 1              │
└─────────────────────────────┘
```

### 차시 완료
모든 행동에 스탬프가 찍히면:

1. 화면 전환 또는 팝업
2. ⭐ 스타가 등장
3. 스타 획득 애니메이션
4. 마리오 캐릭터가 스타를 획득하는 연출
5. 총 스타 수 +1
6. 다음 보상까지 진행률 업데이트

# 5. 칭찬 스탬프 디자인

## 5.1 기본 형태

스탬프는 귀엽고 명확한 **엄지손가락 + 「좋아요」** 형태를 사용한다.

예상 디자인:

```text
       👍
    좋아요!
```

### 디자인 원칙
- 둥글고 귀여운 형태
- 어린 학생이 한눈에 이해할 수 있는 그림
- 작은 화면에서도 인식 가능
- 클릭 전/후 상태가 명확해야 함

### 상태
- 미획득: 회색 또는 흐린 상태
- 획득: 밝고 선명한 상태
- 획득 순간: 살짝 커졌다가 원래 크기로 돌아오는 애니메이션

# 6. 스타 보상 시스템

## 6.1 기본 규칙

**한 차시의 행동 목표를 모두 달성하면 스타 1개**

예:

```text
국어 시간
👍 👍 👍 👍 👍 👍
          ↓
        ⭐ +1
```

## 6.2 스타 누적

- 차시 1회 완료 = ⭐ 1개
- 스타는 학생별로 누적
- 여러 교사가 기록해도 동일 학생의 스타에 합산

## 6.3 30개 보상

학생이 **⭐ 30개**를 달성하면:

> 🎉 축하합니다!  
> 게임 쿠폰을 받았어요!

보상 상태:

```text
현재 스타: 30 / 30

🎮 게임 쿠폰 획득!
```

이후에는 다음 보상 주기를 설정할 수 있도록 확장성을 고려한다.

예:
- 30개마다 쿠폰 1장
- 30개 달성 후 리셋
- 30개 달성 후에도 누적 기록 유지

**MVP에서는 30개 달성 시 1회 쿠폰 지급 방식으로 구현한다.**

# 7. 마리오 연출 관련 설계

## 중요: 저작권/상표권 고려

사용자가 원하는 연출은 `Mario Party Jamboree`의 스타를 참고한 것이지만, 실제 배포·공개 서비스라면 닌텐도 및 마리오 관련 캐릭터/그래픽을 그대로 사용하는 것은 저작권·상표권 문제가 발생할 수 있다.

따라서 개발 단계에서는 다음과 같이 분리한다.

### 프로토타입
- 마리오 파티의 분위기를 참고한 강한 게임 연출
- 별 획득
- 캐릭터가 별을 받는 연출

### 실제 배포 버전
- 자체 제작 캐릭터
- 자체 제작 별
- 자체 제작 게임 보상 이미지

권장 콘셉트:

> **「칭찬 스타」를 모으는 귀여운 모험 캐릭터**

```text

     ↓
[차시 선택]
     ↓
[행동 스탬프]
     ↓
[완료 → 스타]
```

정도의 흐름으로 사용할 수 있어야 한다.

## 8.3 기록 수정

실수로 스탬프를 찍었을 경우:
- 스탬프 취소
- 기록 수정
- 관리자/담임만 수정 가능하도록 설정 가능

# 9. 학생별 기록 화면

교사에게는 학생별 누적 기록을 제공한다.

## 예시

```text
김○○

총 스타       ⭐ 18개
완료 차시     18회
30개까지      12개

최근 기록
10/31  2교시  통합학급       ⭐
10/31  3교시  특수학급 수학  ⭐
```

추가로 다음 통계를 확장할 수 있다.

- 차시별 성공률
- 행동별 성공률
- 통합학급 참여율
- 특수학급 참여율
- 주간/월간 변화

단, **MVP에서는 통계 기능을 최소화하고 기록·보상 기능을 우선 구현한다.**

# 12. 스타 중복 지급 방지

중요한 비즈니스 규칙:

**하나의 차시 기록에는 스타를 최대 1개만 지급한다.**

따라서:

```text
completed = true
AND
starAwarded = false
```

일 때만 스타 +1 및 보상 연출을 실행한다.

스타 지급 후:

```text
starAwarded = true
```

로 변경한다.

이를 통해 화면 새로고침이나 버튼 중복 클릭으로 스타가 여러 번 지급되는 문제를 방지한다.

# 13. 차시 완료 판정

모든 행동 항목이 `awarded = true`이면 완료 처리한다.

```pseudo
if all(stamp.awarded == true):
    session.completed = true

    if session.starAwarded == false:
        student.totalStars += 1
        session.starAwarded = true
        showStarAnimation()
```

```text
1단계: 자리에 앉기
2단계: 5분 동안 자리에 앉기
3단계: 활동이 끝날 때까지 자리에 앉기
```

## 행동별 통계
어떤 행동에서 어려움을 보이는지 확인

## 주간 리포트
학부모에게 다음과 같이 제공:

```text
이번 주 칭찬 스타 ⭐ 8개

잘한 행동
👍 인사하기
👍 자리에 앉기

연습이 필요한 행동
🔄 활동에 집중하기
```

## 가정 연계
학교뿐 아니라 가정에서도 별도 행동 목표를 기록할 수 있도록 확장.

# 18. 향후 행동중재 전문성 확장

단순한 보상 앱을 넘어 **긍정적 행동지원(PBS/PBIS) 기반 행동 데이터 기록 도구**로 발전시킬 수 있다.

예:

```text
행동 목표
   ↓
관찰
   ↓
즉각적 강화
   ↓
누적 성취
   ↓
행동 데이터 분석
   ↓
중재 조정
```

장기적으로는 다음 기능을 추가할 수 있다.

- ABC 행동기록
- 선행사건/행동/결과 기록
- 기능평가 자료
- 행동 빈도 그래프
- 시간대별 행동 변화
- 장소별 행동 변화
- 중재 전/후 비교
- 교사 간 기록 일치도 확인

단, 초기 버전에서는 이런 기능을 넣지 않고 **「빠른 칭찬 기록 + 학생의 성취 경험」에 집중한다.**

# 20. 바이브코딩 시 우선순위

개발자가 한 번에 모든 기능을 만들도록 하기보다 다음 순서로 요청한다.

### 1차 프롬프트
> 「칭찬 스탬프 모으기」의 모바일 우선 웹앱 UI를 만들어줘. 학생이 행동 목표를 하나씩 확인하고 '좋아요 👍' 스탬프를 받을 수 있는 화면과 스타 누적 화면을 구현해줘.

### 2차 프롬프트
> 차시별 행동 템플릿을 추가해줘. 강당 단체 활동, 국어·수학 특수학급 시간, 통합학급 시간의 3가지 템플릿을 사용하게 해줘.

### 3차 프롬프트
> 모든 행동에 스탬프가 찍히면 차시 완료로 판정하고 학생에게 스타 1개를 지급해줘. 스타 지급은 동일 차시에 한 번만 가능하도록 해줘.

### 4차 프롬프트
> 스타를 획득할 때 게임처럼 느껴지는 축하 애니메이션을 추가해줘. 별이 화면 중앙에 등장하고 크게 확대되면서 학생의 누적 스타 수가 증가하도록 해줘.

### 5차 프롬프트
> 학생의 스타가 30개가 되면 게임 쿠폰을 지급하도록 구현해줘. 쿠폰은 중복 지급되지 않도록 하고 지급 기록을 저장해줘.

# 21. 개발 전 결정해야 할 사항

아래 항목은 실제 앱 개발 전에 확정하는 것이 좋다.

## A. 로그인 방식
- [ ] 교사별 계정

학교 내부용이라도 개인정보를 다루므로 실제 서비스에서는:
- 최소한의 개인정보만 저장
- HTTPS
- 인증/권한 관리
- 데이터 접근 제한
- 삭제 정책
등을 고려해야 한다.

## C. 스타 초기화
30개 달성 후:
- [ ] 0개로 초기화
- [ ] 누적 유지 + 쿠폰만 추가
- [ ] 30개 단위로 보상 횟수 증가

**MVP 권장:** 누적 스타 유지 + 쿠폰 지급 횟수 기록

## D. 스탬프 수정
- [ ] 누구나 취소 가능
- [ ] 해당 교사만 취소 가능
- [ ] 관리자만 수정 가능

**MVP 권장:** 해당 차시를 기록한 교사만 수정

## E. 학부모 기능
초기부터 넣을지 결정한다.

**MVP 권장:** 우선 교사 중심으로 개발하고 학부모 화면은 2차 개발

# 24. 개발 시작 전에 추가로 결정하면 좋은 질문

아래 8가지만 정하면 실제 바이브코딩 프롬프트를 훨씬 구체적으로 만들 수 있다.

1. **학생은 1명만 사용하는 앱인가요, 여러 특수교육대상 학생이 사용하는 앱인가요?**
2. **한 학교에서 여러 특수교사·통합학급 교사가 함께 사용할 예정인가요?**
3. **교사 로그인은 필요한가요?** (학교 내부에서만 사용할 경우 간단한 방식도 가능)
4. **학생 이름은 실명으로 표시할 예정인가요, 별명/번호를 사용할 예정인가요?**
5. **학부모가 실제로 앱에 로그인해서 볼 필요가 있나요, 아니면 교사가 화면을 보여주는 정도면 되나요?**
6. **30개 스타 달성 후 스타를 0으로 리셋할까요, 아니면 30 → 31 → 32처럼 계속 누적할까요?**
7. **게임 쿠폰은 실제 쿠폰 이미지/번호를 앱에서 발급할 건가요, 아니면 '쿠폰 획득' 표시만 하면 되나요?**
8. **마리오 캐릭터/스타를 실제 이미지로 사용할 생각인가요, 아니면 '마리오 파티 같은 느낌'의 자체 캐릭터로 만들 생각인가요?**

이 8개가 정해지면 다음 단계에서는 **실제로 바이브코딩 도구에 그대로 붙여 넣을 수 있는 `PRD.md + 구현 프롬프트 + 화면별 요구사항` 형태**로 더 구체화할 수 있다.
